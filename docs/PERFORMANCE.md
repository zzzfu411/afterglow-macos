# 资源占用

目标是让计时器在后台少做事。没有 WebView、Electron、额外常驻服务、网络轮询或动画资源包。

## 0.4.1 误标恢复

- 撤销只在内存保留最近一次完成操作及有界清单信息，不复制专注历史；没有新的定时器、轮询、外部服务或依赖。关闭弹层保留撤销入口，重启后的恢复仍使用现有持久化清单。
- 运行时测试在有撤销记录的空闲状态下持有文件锁，验证没有后台周期读取或写盘；保存失败保留撤销记录以供重试。
- 2026-10-04，Apple Silicon / macOS 27.0.1，安装版 0.4.1、主窗口可见、未开始计时、3 项真实待办与 3 条历史、已完成区展开。5 次短时采样：RSS 108.17 MiB，CPU 0.0%。
- 样本包含系统共享驻留页，并非活动监视器物理内存指标；窗口和缓存状态与旧版样本不同，不据此声称内存降低或保证峰值。独立测试进程已退出。

## 0.4.0 待办清单

- 上限 100 项，清单与专注记录共用已有的文件事务和目录事件监听；输入草稿只存在内存中，不按键写盘。
- 清单使用 LazyVStack，完成区默认折叠；历史仍最多 1,000 条。记录只保留不超过 180 字的事项名称摘要，整份清单不会重复存入每条记录。
- 开始时保存本轮事项 ID，编辑清单不会重建本轮截止时间计时器。仍只有原有的单次截止时间唤醒，无新增服务、依赖或定时轮询。
- 运行时测试实际持有存储锁，验证带清单的空闲状态没有周期读写；读写失败保留原文件和输入草稿。

## 0.3.0 的改动

- 移除每秒读取、解析全部记录的 Timer。目录文件事件触发共享状态同步；原子替换文件后监听仍有效。
- 空闲、暂停时没有计时轮询。运行时只保留一个截止时间 Timer，系统唤醒、时钟变化和应用激活时重新核对状态。
- 可见倒计时使用 SwiftUI 系统时间文本，不每秒发布完整模型或读取历史。
- 系统通知预先调度；关闭窗口或退出应用后不需要用一个自建常驻服务维持提醒。呈现仍受系统通知权限与专注模式影响。
- 历史最多保存 1,000 条，弹层只展示最近 30 条。监听、计时器和观察者的释放已有回归测试。

## 0.3.2 的体验修复

- 历史保存上限仍为 1,000 条，界面改为 LazyVStack 按需显示已有记录，避免“保存了但看不到”，也不一次性构建全部历史行。
- 通知权限在已有的状态与应用激活事件中刷新，不增加轮询。输入校验、按钮说明与错误重试均没有额外后台任务或依赖。
- 独立测试数据包含 1,000 条记录；实机可滚动到最早一条，AX 树只暴露附近的行。测试进程结束后退出。

新增通知与系统事件处理后，本次采样的 RSS 略高；不能将移除轮询说成内存降低。这个短时、单设备样本仅用于记录现状，不是峰值保证、长期泄漏测试或跨产品性能比较。RSS 包含共享驻留页，不等于活动监视器的内存指标，也不包含 WindowServer 等系统进程开销。不同窗口大小、壁纸、系统版本和缓存会影响结果。

## 复测

从活动监视器取得目标进程 PID，先让应用稳定运行，再在普通终端执行：

```sh
python3 scripts/measure-memory.py 12345 --samples 10
```

比较版本时保持窗口尺寸、显示器缩放、外观、计时状态和历史数据相同；分别记录暂停、运行、关闭主窗口以及打开记录后的情况。长期观察应看内存是否在重复交互后持续增长，而不是追求某一次最低读数。

`scripts/test-runtime.sh` 使用临时数据验证空闲／暂停不轮询存储、到期只结算一次，以及反复释放目录监听后文件描述符回收。测试不会修改真实记录或系统通知权限。
